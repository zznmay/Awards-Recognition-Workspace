# 高校学院「学生评奖评优工作台」方案设计

> 定位：学院级评定工具的统一入口 + 数据联动中枢。八个自研评定工具不重写，通过「一份源数据 + 主数据表 + 确认门禁 + 桥接」串成流水线。
> 当前状态：P2 进行中（`index.html`），已接入工具①综测加分计算器、工具②各模块最终加分计算、工具③综测排名计算、工具④奖学金符合等级计算、工具⑤奖学金最终认定、工具⑥三好学生评定、工具⑦优秀学生干部评定、工具⑧行知专业奖学金评定，**8 个工具已全部接入**，「计算 → 版本留存 → 人工选定 → 锁定」闭环覆盖全部评定环节。

## 二、主数据表（唯一数据源）

以**学号**为主键的宽表，按管线层组织，每层带**状态与确认信息**：

```jsonc
{
  "学号": "2023001",
  // 身份层：姓名/年级/班级/专业/专业类型/性别/是否学生干部/是否贫困生
  "品德原始加分": 5, "文体原始加分": 3, "能力原始加分": 3,   // L1（① 产出）
  "品德最终测评分": 91.2, /* ... */                          // L2（② 产出）
  "班级排名": 2, "同年级同专业同类型排名": 3,                 // L3（③ 产出）
  "奖学金符合等级": 1,                                       // L4（④ 产出）
  "最终评定奖学金": "一等奖学金",                             // L5（⑤ 产出）
  "是否符合三好学生": 1 /* 优干/行知 */                       // L6（⑥⑦⑧ 产出）
}
```

批次级 stage 状态（确认门禁 + 版本留存核心，L1/L2 同构）：

```jsonc
"stage": {
  "l1": { "versions": [ /* 每次计算自动留存的版本快照 */ ], "activeVid": "v2" },
  "l2": { "versions": [ /* 每份记录 summary.l1Vid，标识基于哪个上游版本 */ ], "activeVid": "v1" }
}
// 每份版本：{ vid, at, by, confirmedAt, summary, data[] }
// L2 版本 summary 额外含 groups / avgD / avgW / avgN / l1Vid
```

字段字典：现在年级=年级、类型=专业类型，接入层自动归一。

**工具②数据来源分析（接入时确定）**：
- 复用 L1 选定版本（7 项）：学号、姓名、年级、班级、品德/文体/能力原始加分 —— 不需要用户重复导入
- 用户补充（2 项）：**专业、专业类型** —— 工具①不产出，但②按「年级-专业-专业类型」分组归一化必须用到；已归入基本信息库统一维护

## 二之二、参评学生基本信息库（P2 新增，已实现）

**定位**：把 8 个工具输入中「**非工具计算产出、需人工或教务提供**」的数据全部抽出来，在计算开始前**一次性补齐**，之后所有工具只读复用，不再逐个补充。计算类字段（原始加分、最终测评分、排名、等级）由各层工具自动回写，不在此填写。

**16 项字段清单**（配置化 `BASE_FIELDS`，新增或下线字段只需增删一行，UI / 导入 / 模板 / 导出全自动跟随）：

| 类别 | 字段 | 类型 | 消费工具 |
|---|---|---|---|
| 身份（核心） | 学号（主键）、姓名、年级、班级、专业、专业类型 | 文本 | 全部 / ②③④⑥⑧ |
| 学业 | 智育测评、体育成绩、体测成绩 | 数值 | ④⑥⑧ |
| 资格 | 是否挂科、是否处分、体测挂科、是否为学生干部、是否贫困生 | 是否 | ④⑥⑦⑧ |
| 行知专项 | 第一学期智育成绩、第二学期智育成绩 | 数值 | ⑧ |

> 已下线：**院系**、**总成绩/总绩点**（当前流程暂不需要）。需要时把两行加回 `BASE_FIELDS` 即可恢复，无需改任何逻辑。

核心 6 项齐备（`coreReady`）即可启动主线计算；其余按对应工具接入节奏逐步补充。

**交互（延续「给模板 + 批量导入自动识别」的偏好，不做复杂表单）**：

| 能力 | 说明 |
|---|---|
| 完备度总览 | 整体填充百分比 + 进度条 + 缺失核心项提示 |
| 字段清单 | 16 项卡片，标注核心/用途/已填人数/完成度，缺失项自动排前 |

## 二之三、参评学生维度输出原则（P2 新增，已实现）

**核心规则：所有计算均以基础信息库参评名单为唯一基准，不漏人、不进外人。**

1. **输入过滤**（工具①）：导入的附加分明细只匹配基础信息库中的参评学生；非参评学生的明细自动忽略（`dropped` 计数），导入时即时预警条数，计算结果预览再次提示。
2. **零分兜底**（工具①）：参评学生未匹配到任何明细 = 无任何加分，其品德/文体/能力原始加分按 **0** 输出（`zeroFill` 计数，版本摘要记录 `zero`，历史版本表与确认弹窗均标注「含 0 分兜底 N 人」）。
3. **完整性校验（全工具通用）**：`coverageOf(batch, rows)` 校验输出行覆盖全部参评学生；工具②以 `batch.students` 为基准输出（L1 使用版本缺人时该生加分按 0 计并提示 `zeroL1`），遗漏时结果区顶部红色警告条列明学号。
4. 学号匹配统一走 `normSid`（Excel 数字学号带 `.0` 自动抹平），不因格式差异误判「非参评」。

关键函数：`calcBonusEnrolled`（过滤+兜底）、`coverageOf`/`covMissingText`（校验+提示）、`l1Cov`/`l2Cov`/`l3Cov`（最近一次计算的覆盖情况，驱动预览提示条）。后续接入 ④~⑧ 时必须复用同一套模式。

## 二之四、工具③综测排名计算（P2 新增，已实现）

**排名依据**：原始工具③依赖「总成绩 = 品德最终×20% + 智育测评×50% + 文体最终×15% + 能力最终×15%」。工作台不再要求外部导入总成绩列，而是用同一套权重由已有数据合成：

```
综测总成绩 = 智育测评×wZ + 品德最终测评分×wD + 文体最终测评分×wW + 能力最终测评分×wN
```

- 权重**可配置**，默认 **50 / 20 / 15 / 15**（与原工具③口径一致），存于 `batch.rankWeights`；页面上四个输入框即时保存，提供「恢复默认」按钮
- 权重合计必须为 100%，否则拦截计算并提示；改权重不影响已留存版本，重算生成新版本（版本摘要记录当时权重）
- **下沉到工具②**：综测总成绩由「各模块最终加分计算（工具②）」一并产出——工具②输出新增「智育测评」「总成绩」两列（智育测评取自基础信息库、总成绩按上述公式合成），写入 L2 版本与主数据表，**工具④等下游可直接读取，无需再算一遍**；工具③直接复用该结果排名

**排名规则**（移植原工具③，规则不变）：按总成绩降序，**分数相同并列同名次，下一名次跳号**；两个维度独立计算：
- 班级维度：`班级排名` / `班级人数`
- 同年级同专业同类型维度：`同年级同专业同类型排名` / `同年级同专业同类型人数` / `综测排名比例`（= 排名 ÷ 人数，4 位小数，供工具④判定等级直接使用）

**数据准备**：
- 姓名/班级/专业/专业类型与三项最终测评分复用 L2 使用版本；`智育测评` 取自基础信息库
- 智育测评是总成绩主成分，缺失会导致排名失真 → **强制补齐**才可计算（`zhiyuMissing` / `rankReady`），提供模板下载 + 列名自动识别导入（智育测评/智育成绩/学业成绩）+ 跳转信息库
- 参评维度：以 `batch.students` 为基准，L2 版本缺某生时其三项最终测评分按 0 计并提示 `zeroL2`

关键函数：`calcRank(rows,w)` / `rankBy`（并列跳号）/ `rankRows`（参评维度取数）/ `rankWeights` / `pushL3Version` / `applyL3Version`；`L3_KEEP` 六个字段回写主数据表。

## 二之五、工具④奖学金符合等级计算（P2 新增，已实现）

**判定规则**（默认，页面可改）：`达标 = 排名比例 ≤ 阈值 且 智育测评 ≥ 门槛 且 通过全部硬性条件`；命中第一档即最高等级（按 level 升序，比例与智育双门槛，硬性任一不过即整体不达标）。

| 等第 | 排名比例 | 智育测评 | 硬性条件 |
|---|---|---|---|
| 一等奖 | ≤ 10% | ≥ 85 | 不挂科、不处分、体测不挂科 |
| 二等奖 | ≤ 20% | ≥ 80 | 同上 |
| 三等奖 | ≤ 35% | ≥ 75 | 同上 |

- 门槛三档「排名比例 / 智育门槛」与三项硬性是否要求，在工具④页面直接改、即时保存（存 `batch.gradeRules`），可一键「恢复默认门槛」；改动不影响已留存历史版本，重算生成新版本（摘要记录当时门槛）
- 产出 `奖学金符合等级`（1/2/3/0）与 `是否符合`（一等奖/二等奖/三等奖/不符合）；`calcGrade(rows,rules)` 按 `tiers[].name` 输出等第文本，与原始工具对齐
- 数据来源全部复用：排名比例/排名/人数取 L3 使用版本（`L3_KEEP`）；智育测评取基础信息库；硬性条件（是否挂科/是否处分/体测挂科）取基础信息库，`normYN` 归一化（0 = 通过）。硬性条件缺失视为未补齐并**拦截计算**（评奖关系重大，不默认通过）——区别于 ②③ 的零分兜底
- 参评维度：以 `batch.students` 为基准，L3 使用版本缺某生时其排名/比例/智育按 0 计（`zeroL3`），必然「不符合」，并提示
- 版本留存：`pushL4Version` 记录 一等/二等/三等/不符合 计数 + 基于 L3 版本号 + 门槛文本 + 计算人；选定后 `applyL4Version` 经 `L4_KEEP`（奖学金符合等级、是否符合、综测排名比例、智育测评、是否挂科、是否处分、体测挂科）回写主数据表，供工具⑤复用
- 上游（L1/L2/L3）切换使用版本 → 工具④版本与确认状态级联清空，重建「重新运行工具④」待办

关键函数：`L4`/`l4Done`/`l4Confirmed`/`activeL4` / `gradeRules` / `gradeRows`（参评维度取数）/ `calcGrade` / `hardMissing` / `gradeReady` / `pushL4Version` / `applyL4Version`。

## 二之六、工具⑤奖学金最终认定（P2 新增，已实现）

**判定规则**（忠实于原始工具）：依据「奖学金符合等级（来自工具④ L4_KEEP）+ 名额分配表」逐级降级认定每名学生的最终奖学金等第（一等奖学金 / 二等奖学金 / 三等奖学金 / 无）。

- 分配前按「等级升序 → 班级 → 班级排名」排序，保证高等级、同班优先吃名额：
  - 一等资格（符合等级 = 1）：优先吃一等名额，一等不足 → 顺降二等、再三等
  - 二等资格（符合等级 = 2）：优先吃二等名额，不足 → 顺降三等
  - 三等资格（符合等级 = 3）：只吃三等名额
  - 不符合（符合等级 = 0）：直接「无」，不参与名额分配
- 名额只读 `batch.quota` 的班级名额，分配时按档位依次扣减，耗尽则该生「无」；若某合格学生（1~3 等）所在班级未配置名额（`__clsMissing`），预览与版本摘要均提示「名额缺班 N 人」，需回名额表补齐
- 最终结果按「班级 → 班级排名」排序输出，便于核对与公示

**数据来源**：符合等级、是否符合、班级、班级排名、专业、专业类型、综测排名比例全部复用主数据表（L4_KEEP 已下沉），无需重复导入；唯一外部补充数据「名额分配表」单独建 `batch.quota`（数组，每项 `{班级, 一等奖学金名额, 二等奖学金名额, 三等奖学金名额}`），跟随批次，工具内可批量导入 + 表格增删改。

**名额分配表交互**（与基本信息库 `importBaseProfile` 模式一致，但面向「班级聚合」数据）：模板下载（班级/一/二/三等名额三列）、列名别名识别导入（一等名额/一等奖学金名额/一等奖学金/一等 等同义归一）、同班自动去重、表格单元格可改、可增删班级行。

**版本留存**：`pushL5Version` 记录 一等/二等/三等/无 计数 + 基于 L4 版本号 + 名额缺班人数 + 名额摘要文本 + 计算人；选定后 `applyL5Version` 经 `L5_KEEP`（最终评定奖学金）回写主数据表，供工具⑥复用。上游（L1/L2/L3/L4）切换使用版本 → 工具⑤版本与确认状态级联清空（`invalidateDownstream` 已补全至 `l1||l2||l3||l4` 清 L5）。

关键函数：`L5`/`l5Done`/`l5Confirmed`/`activeL5` / `quotaMap` / `quotaReady` / `l5Ready` / `calcFinal` / `pushL5Version` / `applyL5Version`；`L5_KEEP`（最终评定奖学金）单字段回写主数据表。

## 二之七、工具⑥三好学生评定（P2 新增，已实现）

**判定规则**（忠实于原始工具，逐学生按 7 条件全满足才为「是」）：

| # | 条件 | 数据来源 |
|---|---|---|
| ① | 最终认定为 **一/二等奖学金** | `最终评定奖学金`（L5_KEEP 回写）|
| ② | 体育成绩 ≥ 80 | 基本信息库 `体育成绩`（for:⑥）|
| ③ | 智育测评 ≥ 80 | `智育测评`（L2_KEEP 回写）|
| ④ | 学年综测班级排名比例 ≤ 0.10 | = 班级排名 ÷ 班级人数（L3_KEEP 回写），**非**「综测排名比例」|

## 二之九、工具⑧行知专业奖学金评定（P2 新增，已实现）

**定位**：**L5 的分支**（独立线，不依赖 ⑥⑦）——只有 L1~L5 切换使用版本会使其失效。

**判定规则**（忠实于原始工具）：

| 步骤 | 规则 | 说明 |
|---|---|---|
| 排名 | 按「年级+专业+专业类型」分组，组内对第一、二学期智育成绩分别做**降序竞赛排名** | 并列同名次、下一不同分跳至位次 |
| 进步比 | 第二学期排名 ÷ 第一学期排名 | ≤ 0.60 视为有进步 |
