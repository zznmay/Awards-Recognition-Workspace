# 一、工具③综测排名计算

## 排名依据：可配置权重合成

原始工具③需要外部导入「总成绩」列，但该字段已下线，改为由工作台已有数据合成：

```
综测总成绩 = 智育测评×70% + 品德最终×10% + 文体最终×10% + 能力最终×10%
```

四个权重在页面上直接改，改完即时保存（默认 70/10/10/10，可一键恢复）。合计必须等于 100%，否则拦截计算。改权重不会影响已留存的历史版本，重新计算生成新版本，版本摘要会记录当时用的权重。

## 输出字段

| 维度 | 字段 |
|---|---|
| 成绩 | 综测总成绩 |
| 班级 | 班级排名、班级人数 |
| 同年级同专业同类型 | 同年级同专业同类型排名、同年级同专业同类型人数、综测排名比例（排名÷人数） |

排名规则与原始工具一致：分数降序、**同分并列同名次且下一名次跳号**（1、1、3、4…），两个维度各自独立计算。「综测排名比例」是工具④判定奖学金等级的直接输入，无需再算一次。

输出排序（用户要求）：所有工具③输出（最近计算预览表、历史版本明细表、下载 CSV）统一按 **班级升序 → 同年级同专业同类型排名升序 → 学号兜底** 排列，班级连续成块、块内按分组排名升序，便于核对。

## 需要补的数据

- 姓名、班级、专业、专业类型与三项最终测评分：全部复用工具②结果
- **智育测评**：取自基础信息库，是总成绩的主成分，缺失会让排名失真，因此缺了就拦住不让算。补齐方式与分组信息一致——下载模板（已预填名单）→ 填一列 → 导入自动识别（列名可写作智育测评/智育成绩/学业成绩），或去信息库一次补齐全流水线复用

## 参评维度

以参评名单为基准输出，工具②使用版本里缺某生时，其三项最终测评分按 0 计并在结果区提示；输出不完整时红色警告条列出遗漏学号。

# 二、工具④奖学金符合等级计算

判定每个参评学生符合哪一等第（一/二/三等奖）奖学金，判定依据全部复用上游与信息库，无需重复导入。

## 判定规则（默认，页面可改）

```
达标 = 排名比例 ≤ 阈值 且 智育测评 ≥ 门槛 且 通过全部硬性条件
命中第一档即最高等级（按 level 升序，比例与智育双门槛，硬性任一不过即整体不达标）
```

| 等第 | 排名比例 | 智育测评 |
|---|---|---|
| 一等奖 | ≤ 10% | ≥ 85 |
| 二等奖 | ≤ 20% | ≥ 80 |
| 三等奖 | ≤ 35% | ≥ 75 |

硬性条件（默认全部要求通过）：**不挂科、不处分、体测不挂科**——读取基础信息库字段 `是否挂科/是否处分/体测挂科`（`normYN` 归一化，0 = 通过）。

## 数据来源（全部复用，零重复录入）

| 输入 | 来源 |
|---|---|
| 综测排名比例、班级排名/人数、同分组排名/人数 | 工具③使用版本（L3_KEEP） |
| 智育测评 | 基础信息库（也已下沉在 L2/L3） |
| 是否挂科 / 是否处分 / 体测挂科 | 基础信息库（硬性条件，评奖关系重大，缺失视为未补齐并拦截计算，不默认通过） |

## 门槛可配置

三档「排名比例 / 智育门槛」与三项硬性是否要求，在工具④页面直接改、即时保存（存 `batch.gradeRules`），可一键「恢复默认门槛」。改动**不影响已留存的历史版本**，重新计算生成新版本，版本摘要记录当时的门槛文本。

## 输出与版本

- 产出字段 `奖学金符合等级`（1/2/3/0）、`是否符合`（一等奖/二等奖/三等奖/不符合）
- 每次计算自动留存一份历史版本（摘要含 一等/二等/三等/不符合 计数 + 基于 L3 版本号 + 门槛文本 + 计算人）
- 选定使用版本后，通过 `L4_KEEP`（奖学金符合等级、是否符合、综测排名比例、智育测评、是否挂科、是否处分、体测挂科）写入主数据表，供工具⑤复用
- 上游（L1/L2/L3）切换使用版本 → 工具④版本与确认状态被级联清空，自动重建「重新运行工具④」待办
- 硬性条件缺失时，提供「下载待补齐名单」引导去信息库一次性补齐

## 参评维度

与 ②③ 一致：以参评名单为基准输出；工具③使用版本里缺某生时，其排名/比例/智育按 0 计（必然「不符合」）并在结果区 `zeroL3` 提示；输出不完整时警告条列出遗漏学号。

# 三、工具⑤奖学金最终认定

依据「符合等级 + 名额分配表」逐级降级认定每名学生的最终奖学金等第。判定逻辑忠实于原工具：一等资格优先吃一等名额，不足则顺降二等、再三等；二等同理；三等只吃三等。

## 数据来源（全部复用，名额表单独补）

| 输入 | 来源 |
|---|---|
| 奖学金符合等级（1/2/3/0）、是否符合、班级排名、班级 | 工具④使用版本（L4_KEEP，下沉在主数据表） |
| **名额分配表**（班级 → 一/二/三等名额） | **外部补充**：教务给定，存在 `batch.quota`，可在工具⑤内「下载模板 → 批量导入自动识别」或表格内增删改 |

名额分配表属「非计算产出、按班级聚合」数据，不适合塞进以「学生」为主键的信息库，故单独建表、跟随批次走。空表/未导入则结果全部为「无」。

## 认定规则（逐级降级）

```
对每名参评学生（以主数据表为基准）：
  符合等级 = 1：一等名额>0 → 一等奖学金；否则 二等名额>0 → 二等奖学金；否则 三等名额>0 → 三等奖学金；否则 无
  符合等级 = 2：二等名额>0 → 二等奖学金；否则 三等名额>0 → 三等奖学金；否则 无
  符合等级 = 3：三等名额>0 → 三等奖学金；否则 无
  符合等级 = 0（不符合）：无
所在班级未出现在名额分配表 → 无（并标记「名额缺班」）
```

分配顺序：先按 符合等级升序、再班级、再班级排名升序遍历，保证高优先级学生先占用名额；输出统一按 **班级升序 → 班级排名升序** 排列。

## 输出与版本

- 产出字段 `最终评定奖学金`（一等奖学金/二等奖学金/三等奖学金/无）
- 每次计算自动留存一份历史版本（摘要含 一等/二等/三等/无 计数 + 名额缺班数 + 基于 L4 版本号 + 名额摘要文本 + 计算人）
- 选定使用版本后，通过 `L5_KEEP`（最终评定奖学金）写入主数据表，供工具⑥等荣誉评定复用
- 上游（L1/L2/L3/L4）任意一层切换使用版本 → 工具⑤版本与确认状态被级联清空，自动重建「重新运行工具⑤」待办
- 名额表支持 CSV/XLSX 导入，列名别名识别（一等名额/一等奖学金名额/一等奖学金/一等 等均可识别、同班去重）

## 参评维度

以参评名单为基准输出；工具④使用版本里缺某生（无 `奖学金符合等级`）时，该生不计入认定结果并在完整性校验里标为遗漏；班级不在名额表的合格学生标注「名额缺班」，其余与 ②③④ 一致。

# 四、工具⑥三好学生评定

> 输入：L5 最终认定（一/二等奖学金） + 体育成绩（信息库） + L2 智育测评 + L3 班级排名·班级人数（排名比例） + 信息库 体测挂科/是否处分/是否挂科
> 输出：`是否符合三好学生`（1/0）、`学年综测班级排名比例`，复用主数据表，供荣誉类下游工具消费

## 判定规则（忠实于原工具，逐学生 7 条件全满足才为「是」）

| # | 条件 | 说明 |
|---|---|---|
| ① | 最终认定为 **一/二等奖学金** | 读 `最终评定奖学金`（L5_KEEP 回写） |
| ② | 体育成绩 ≥ 80 | 来自基本信息库 `体育成绩` |
| ③ | 智育测评 ≥ 80 | 读 `智育测评`（L2_KEEP 回写） |
| ④ | 学年综测班级排名比例 ≤ 0.10 | = 班级排名 ÷ 班级人数（L3_KEEP 回写），非「综测排名比例」 |
| ⑤ | 体测未挂科 | `体测挂科`=否 |
| ⑥ | 无处分 | `是否处分`=否 |
| ⑦ | 无挂科 | `是否挂科`=否 |

任一条件不满足即判定为「否」，并在版本摘要中按原因分布计数（非一/二等奖、体育<80、智育<80、排名比>0.10、体测挂科、有处分、有挂科）。

## 数据来源与版本机制

- 计算输入全部复用既有层：最终认定、智育测评、班级排名、班级人数、体测挂科、是否处分、是否挂科均已在主数据表；**唯一需补齐的新字段是 `体育成绩`（信息库 16 字段之一）**。
- 就绪门禁 `sanhaoReady` = L5 已确认 且 参评学生 `体育成绩` 齐备；体育成绩缺失时工具⑥显示「待补体育成绩」并引导至基本信息库补齐（与工具④补齐硬性条件、工具⑤补名额表同构）。
- 版本机制 `L6` / `l6Done` / `l6Confirmed` / `activeL6` 与 L1~L5 同构：`pushL6Version` 留存（含符合率与原因分布摘要），`applyL6Version` 经 `L6_KEEP`（是否符合三好学生、学年综测班级排名比例）写入主数据表。
- 上游（L1~L5）任意一层切换使用版本 → 工具⑥版本与确认状态被级联清空（`invalidateDownstream` 已补全至 `l1||l2||l3||l4||l5` 清 L6），自动重建「重新运行工具⑥」待办。

# 五、工具⑦优秀学生干部评定

> 输入：L6 三好学生（使用版本，输出透传【是否符合三好学生】列供对照）+ L3 班级排名·班级人数 + L6 学年综测班级排名比例（复用）+ L1 品德原始加分（算品德测评班级排名）+ 信息库 是否学生干部·体测挂科·是否处分·是否挂科
> 输出：`是否符合优秀学生干部`（1/0）、`品德测评班级排名比例`、复用主数据表

## 判定规则（忠实于原工具，逐学生 6 条件全满足才为「是」）

| # | 条件 | 说明 |
|---|---|---|
| ① | 学年综测班级排名比例 ≤ 0.30 | = 班级排名 ÷ 班级人数，复用 L6 已算字段 `学年综测班级排名比例` |

| ③ | 体测未挂科 | `体测挂科`=否 |
| ④ | 无处分 | `是否处分`=否 |
| ⑤ | 无挂科 | `是否挂科`=否 |
| ⑥ | 确为学生干部 | `是否为学生干部`=1（信息库字段，for:⑦） |

**按用户要求，工具⑦输出结果中新增一列【是否符合三好学生】，值直接取自主数据表 `是否符合三好学生`（L6_KEEP 回写字段），仅作对照透视、不参与优干判定。**

## 数据来源与版本机制

- 计算输入全部复用既有层：班级排名、班级人数、学年综测班级排名比例、品德原始加分、体测挂科、是否处分、是否挂科均已在主数据表；**唯一新增依赖是 `是否为学生干部`（信息库 16 字段之一，for:⑦）**。
- 就绪门禁 `ganbuReady` = L6 已确认 且 参评学生 `是否为学生干部` 齐备；该字段缺失时引导至基本信息库补齐。
- 品德测评班级排名比例由 `moralityRankInClass(b)` 按班级聚合、品德原始加分降序（竞赛排名）实时计算，再 ÷ 班级人数。
- 版本机制 `L7` 与 L1~L6 同构：`pushL7Version` 留存（含符合率与原因分布：综测比>0.30、品德比>0.30、体测挂科、有处分、有挂科、非学生干部），`applyL7Version` 经 `L7_KEEP`（是否符合优秀学生干部、学年综测班级排名比例、品德测评班级排名比例）写入主数据表。
- 上游（L1~L6）任意一层切换使用版本 → 工具⑦版本与确认状态被级联清空（`invalidateDownstream` 已补全至 `l1||…||l6` 清 L7）。

# 六、工具⑧行知专业奖学金评定（本轮新增）

> 输入：L5 最终认定（推导「是否有综合奖学金」）+ 信息库 两学期智育成绩·是否贫困生·体测挂科·是否处分·是否挂科
> 输出：`是否符合行知专业奖学金`（1/0）、`第二学期与第一学期排名之比`、两学期智育成绩排名（`L8_KEEP` 四字段回写主数据表）
> 位置：**L5 的分支**（独立线，不依赖 ⑥⑦）——只有 L1~L5 切换版本会使它失效

## 判定规则（忠实于原工具）

1. **分组排名**：按「年级 + 专业 + 专业类型」分组，组内分别对第一学期、第二学期智育成绩做**降序竞赛排名**（并列同名次、下一不同分跳至位次）。
2. **进步比** = 第二学期排名 ÷ 第一学期排名。
3. **基础筛选（7 项全满足）**：

| # | 条件 | 说明 |
|---|---|---|
| ① | 进步比 ≤ 0.60 | 视为本学期有进步 |
| ②③④ | 体测未挂科 / 无处分 / 无挂科 | 信息库 |
| ⑤ | 无综合奖学金 | **由 L5 最终认定自动推导**：最终评定奖学金 ≠「无」即为有（一/二/三等奖学金均计） |
| ⑥⑦ | 第一、二学期智育成绩均 > 0 | 信息库 |

4. **名额分配**：符合条件的贫困生数 P → 总名额 = **floor(P ÷ 0.30)**；**贫困生全部入选**，剩余名额（总名额 − P）按进步比**升序**（进步越大越优先）取非贫困生。

> 关键决策：原工具的「是否有综合奖学金」是手工录入列，工作台改为**由 L5 最终认定自动推导**（计算类字段复用，无需手工补录），并在预览/明细/CSV 中如实展示。

## 数据来源与版本机制

- 输入全部复用既有层：体测挂科/处分/挂科（L4 已保证）、最终评定奖学金（L5_KEEP）；**唯一需补齐的新字段是 `第一学期智育成绩`、`第二学期智育成绩`（信息库 16 字段之一，for:⑧）**，`是否贫困生` 也已预留。
- 就绪门禁 `xingzhiReady` = L5 已确认 且 参评学生「两学期智育成绩 + 是否贫困生」齐备；缺失时引导至基本信息库补齐。
- 版本机制 `L8` 与 L1~L7 同构：`pushL8Version` 留存（含基础合格人数、总名额、入选贫困/非贫困数、原因分布），`applyL8Version` 经 `L8_KEEP`（是否符合行知专业奖学金、第二学期与第一学期排名之比、第一学期智育成绩排名、第二学期智育成绩排名）写入主数据表。
- **级联特殊性**：工具⑧是 L5 的分支，`invalidateDownstream` 仅 `l1||…||l5` 清 L8；切换 L6/L7 **不影响** L8。

# 七、参评学生维度输出原则

所有计算以基础信息库参评名单为唯一基准，**不漏人、不进外人**。

| 规则 | 行为 | 提示方式 |
|---|---|---|
| 输入过滤 | 导入的附加分明细只匹配参评学生，非参评明细自动忽略 | 导入完成即 toast 预警 + 结果预览提示条（`dropped` 条数） |
| 零分兜底 | 参评学生没匹配到任何明细 = 无任何加分，品德/文体/能力原始加分按 **0** 输出 | 版本摘要记 `zero`，历史版本表与确认弹窗标注「含 0 分兜底 N 人」 |
| 完整性校验 | 输出行数必须等于参评人数，否则列出遗漏学号 | 结果区顶部红色警告条 + toast；②③通用复用 |

- 工具①新增 `calcBonusEnrolled(detail, batch)`：先按学号集合过滤输入，再以 `batch.students` 为基准遍历输出
- 通用 `coverageOf(batch, rows)` / `covMissingText(cov)` 供 ②~⑧ 直接复用
- 工具②同步改为参评维度：L1 使用版本若缺某生，该生三项加分按 0 计并提示 `zeroL1`
- 工具③同样以参评名单为基准：L2 使用版本若缺某生，该生三项最终测评分按 0 计并提示 `zeroL2`
- 学号匹配统一走 `normSid`，Excel 数字学号 `2023001.0` 不会误判为「非参评」

# 八、参评学生基本信息库

把 8 个评定工具输入中「非工具计算产出、需人工或教务提供」的数据全部抽出来，收进一个统一的信息库，在计算开始前一次性补齐，之后所有工具只读复用，不再逐个补充。

## 字段清单（16 项，配置化）

| 类别 | 字段 | 类型 | 消费工具 |
|---|---|---|---|
| 身份（核心） | 学号（主键）、姓名、年级、班级、专业、专业类型 | 文本 | 全部 / ②③④⑥⑧ |
| 学业 | 智育测评、体育成绩、体测成绩 | 数值 | ③④⑥⑧ |
| 资格 | 是否挂科、是否处分、体测挂科、是否为学生干部、是否贫困生 | 是否 | ④⑥⑦⑧ |
| 行知专项 | 第一学期智育成绩、第二学期智育成绩 | 数值 | ⑧ |

核心 6 项齐备即可启动主线计算，其余按工具接入节奏逐步补。

**增删字段只改 `BASE_FIELDS` 一张表**，字段清单、模板、导入识别、导出、完备度统计全自动跟随。已下线的「院系」「总成绩/总绩点」如需恢复，把对应行加回即可，无需改任何逻辑；导入的名单里若仍含这两列，会自动忽略且不报错。

计算类字段（原始加分、最终测评分、排名、等级）由各层工具自动回写主数据表，不在此填写。

## 用户怎么用

1. 下载名单模板 —— 已有数据全部预填，只补空列；是否类导出为「是/否」便于填写
2. 拖入文件 —— CSV / XLSX，列名自动识别：
   - 别名匹配：学号＝学籍号＝考生号；专业＝所学专业；专业类型＝类别＝生源类型；体育课成绩＝体育成绩
   - 学号规范化：Excel 数字学号 `2023001.0` 自动抹平
   - 学号缺失时按「姓名＋班级」兜底；都匹配不上才计为未匹配并逐条提示
   - 空格子不覆盖已有数据；名单里的新学生自动建档
3. 名册表内可搜、可筛「仅看有缺失」，单元格直接改（是否类为下拉三态），改动即时落盘
4. 也可「下载待补齐名单」——只导有缺失的学生，并标注每人缺哪些字段
5. **重置数据**——两档可选：

   | 选项 | 影响 | 二次确认 |
   |---|---|---|
   | 仅清空字段值，保留名单 | 学号、姓名保留，其余 14 项基础字段清空；已留存的 L1/L2 计算版本与确认状态**不受影响** | 否 |
   | 清空整个名单（含计算结果） | 删除全部学生、附加分明细、L1/L2 版本与系统待办，批次回到空状态；自定义待办保留 | 是（提示不可撤销、建议先导出 JSON 备份） |

   名单为空时点击重置不弹窗，只提示「无需重置」。

## 与管线的联动

- 管线首位新增「基础信息库」步骤，点击直达
- 首页统计卡新增「基础信息完备度」（百分比 + 进度条）
- 核心字段缺失时，首页动态注入一条引导待办（**不落库**，补齐后自动消失）
- 工具②的分组信息缺口改为引导「去基本信息库补齐」，保留就地导入作备用；库里已补齐时开箱即算
- 示例数据预置了核心字段（非核心刻意留白演示补齐），因此打开即可跑通①→②→③
- 工具③的智育测评缺口同样引导「去基本信息库补齐」，保留就地导入作备用
- **综测总成绩公式按原工具③口径修正为 智育50% + 品德20% + 文体15% + 能力15%**（默认权重，可配置），并下沉到工具②：工具②输出新增「智育测评」「总成绩」两列，写入 L2 版本与主数据表，工具④等下游直接读取

## 本轮修掉的坑

- 导入结果提示被随后的视图重渲染冲掉 → 改为模块级 `baseMsg` 状态驱动渲染，切换批次时清空
- 模板导出排序比较器写成 `> ? 1 : -1`（不稳定）导致首行乱序 → 改为返回 -1/0/1
- 是否类字段导出为 0/1 不便人工填写 → 导出为「是/否」，导入时再归一化
- 「必须有学号列」限制过严 → 无学号列时允许凭「姓名＋班级」导入（仅不能新建建档）
- HTML 片段字符串漏闭合单引号（`'...";` 应为 `'...';`）→ 固定动作：改完必须抽取内嵌脚本跑 `node --check`
- 上游切换级联失效补全：原本 `invalidateDownstream(b,"l2")` 只清 L4、漏清 L3（排名完全依赖 L2 最终分，切 L2 版本后 L3 必然失真却未失效）→ 现改为 `l1` 清 L2、`l1||l2` 清 L3、`l1||l2||l3` 清 L4、`l1||l2||l3||l4` 清 L5，形成完整级联（①→②→③→④→⑤ 任一切换都清空其下游全部层）
- `calcGrade` 等级文本原输出「1等奖」与原始工具「一等奖」不一致 → 改为按 `tiers[].name` 输出「一等/二等/三等奖」，与原始工具对齐
- 工具⑤「名额缺班」标记收窄：仅对符合等级有效（1~3）但所在班级未配置名额的合格学生标记 `clsMissing`，不符合（0 等）学生本就「无」、不再误报缺班
- **工具④已确认仍显示「待接入」徽标**：根因 `toolStatus(t)` 漏 `t.id==="level"` 分支，函数末尾 fallback `return "locked"` → 命中徽标兜底文本「待接入」→ 在 `rank` 与 `final` 之间补 level 分支（`l3Confirmed ? (l4Confirmed→done : l4Done→pending : ready) : gate`），与 PIPE l4 对齐；新写 `/tmp/pjpy_test_toolstatus.js` 28/28 端到端回归，确保后续接入 ⑥⑦⑧ 不再漏分支
- **工具⑥版本摘要 `fail` 键被覆盖**：`pushL6Version` 的 summary 对象里 `fail:n-pass`（不符合总数）与 `fail:bd("有挂科")`（原因分布）键名重复，后者覆盖前者，导致 `不符合` 计数错乱、`有挂科` 原因计数串到总不符合数 → 将原因分布键改名为 `failc`，summary.fail 恢复为 `n-pass`；`viewL6Version` 的「有挂科」引用同步改为 `v.summary.failc`。测试 68/68 全绿后确认修复

- **工具⑦测试初次失败的根因（测试侧，非代码 bug）**：① 工具①的运行按钮 id 是 `tool-run` 而非 `t1-run`（其余工具为 `t2-run`~`t7-run`）→ 点击失效导致整条 demo 链路未打通；② L1 没有 `doApplyL1`（只有 `confirmL1()` / `applyL1Version(batch,vid)`），测试误调用了不存在的 `doApplyL1` → 统一改为 `applyL*Version(B(),'v1')`；③ 测试 A3 用例设计错误：把品德最低的学生放在 50 人大班，其品德排名 9/50=0.18 仍 ≤0.30 应判「是」，却在断言里期望「否」→ 改为单独小班组（4 人垫底，品德比 1.0>0.30）以真正隔离品德门槛
- **激活工具⑦后 `pjpy_test_sanhao.js` 的 1 项断言失效**：该测试用 `ganbu` 作为「未激活工具 fallback → locked」的样例，工具⑦激活后该断言自然不成立 → 改为指向仍未接入的工具⑧ `xingzhi`（行知专业奖学金），sanhao 测试恢复 68/68
- **工具⑧测试初次失败的根因（测试侧）**：`openTool("xingzhi")` 会清空 `calc8Results` 最近计算缓存 → 下载按钮（仅在有结果时渲染）不存在，`#t8-dl` 点击无效 → K 段需先点 `#t8-run` 重算、再点下载
- **激活工具⑧后 `pjpy_test_sanhao.js` 的「未激活工具 fallback」样例再次失效**：此时 8 个工具已全部激活，无「未激活工具」可测 → 该断言改为「`TOOLS.every(t=>t.active)` 全部激活 + 已激活工具均不命中 locked fallback」，sanhao 测试 68→69
