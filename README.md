# 评奖评优工作台

面向高校奖学金评定流程的单文件 Web 应用仓库。本仓库从原有存档目录整理而来，**仅纳入最新有效版本**，供后续使用 Git / GitHub 做版本管理。整理过程未改动任何原有文件内容与功能。

---

## 一、项目概述

| 项目 | 说明 |
|---|---|
| 应用形态 | 单个 `index.html`，纯前端、零构建、无本地外部资源；登录能力依赖 WorkBuddy 云服务（CDN 引入 SDK，无需 npm） |
| 运行方式 | **通过发布后的 https 链接访问**（手机号登录需要线上域名）；本地 `file://` 打开会停在登录页提示 |
| 业务范围 | 基础信息库 + 8 个评定工具（综测加分、模块加分、综测排名、符合等级、最终认定、三好学生、优秀学生干部、行知专业奖学金）+ 公示管理 |
| 数据存储 | 登录后的工作数据：浏览器 `localStorage`（键 `wb_pjpy_state_v1`，工作层）+ 云数据库 `pjpy_state` 单用户状态文档（账号层，RLS 仅本人可读写）。归档库 `wb_pjpy_archive_v1` 仍**只存本机**，不参与云同步 |
| 访问控制 | 未登录时 `body.auth-locked` 隐藏工作台并停渲染，任何学生数据都不呈现；`?pub=…` 公示查询页为公开页面，不受门禁限制 |
| 核心机制 | 逐层「确认门禁」（确认锁定后下一层才可用）与「版本留存」（`stage.lX.versions`），上游切换版本会通知下游 |

## 二·附、账号与云同步（本次新增）

| 项目 | 说明 |
|---|---|
| 登录方式 | 手机号 + 短信验证码（WorkBuddy 云服务 Auth）。首次验证通过自动注册，不设密码，账号即手机号 |
| 跨端一致 | 一个账号一行状态文档（表 `pjpy_state.payload` 存 `state` 全量快照）。登录时拉取云端并用 `mergeStates()` 做字段级合并，同一手机号在手机/电脑得到同一份数据；保存后 2.5s 防抖推送，切后台立即冲刷，回到前台自动对账 |
| 冲突策略 | 沿用 Gist 通道同一套收敛语义：空值不覆盖、双方都有值按对象 `mtime` 较新者胜出、同级确定性取远端；因此两端同时改动也不会整包互相覆盖 |
| 门禁 | 未登录不渲染 `#app` / `#mnav`（含骨架屏），登录后解除；`?pub=` 公示页例外 |
| 退出登录 | 二次确认 → 冲刷未推送改动 → `signOut()` → 清除本机工作数据缓存（云端保留）；归档库不清除 |
| 会话失效 | 数据库返回 401/未认证时回到登录页并保留本机数据，重新登录同一账号自动合并上传 |
| 账号切换 | 本机缓存带 owner 标记；换手机号登录先清本机工作数据与归档库，避免跨账号串数据 |
| 回滚 | 「数据与工具」页原 GitHub Gist 同步面板已由「账号与云同步」替代，相关代码完整保留，把 `GIST_SYNC_ENABLED` 改为 `true` 即恢复旧通道（两套通道不可同时启用） |

## 四、快速使用

**线上使用（推荐）**：通过发布后的 https 链接访问，手机号验证码登录后即可使用；手机与电脑登录同一手机号即看到同一份数据。

**本地调试**：本地静态服务可用于改代码与看界面，但域名与云端登记的发布域名不一致时登录会被拒绝（Origin 校验），属平台边界：

```bash
cd 评奖评优工作git
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000/index.html
```

> 注意：登录后业务数据以账号为归属并自动同步云端；未登录不展示任何数据。归档学年仅存本机，换账号登录会被清除，请用「导出归档文件」单独留档。

## 六、版本管理约定

1. **单一主文件**：只维护根目录 `index.html`，不再手工复制「XX版本.html」留档；历史版本由 Git 提交历史与标签追溯。
2. **提交粒度**：一次功能性改动对应一次提交，提交信息建议 `type: 简述`（如 `fix: 修正公示查询页缓存`、`feat: 等级调整面板增加搜索`）。
3. **版本标签**：可发布节点打 `vX.Y.Z` 标签；重大功能递增次版本号，缺陷修复递增修订号。当前基线标签为 `v3.4.0`。
4. **改动校验**：每次修改后用 `shasum -a 256 index.html` 核对，并在提交前确认工作区 diff 仅在预期范围。
5. **敏感数据**：学生名单、成绩、`localStorage` 导出文件、备份 JSON 一律不得提交，相关模式已由 `.gitignore` 拦截。
